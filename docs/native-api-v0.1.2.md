## Reproducible wire schema

`approval/schema.py` embeds a compressed descriptor generated by
`grpcio-tools==1.76.0` from the above original schema files. It retains original
message/field/enum/oneof/map definitions required by seven whitelisted RPCs.
Unrelated APIs, source comments and custom authorization descriptor options are
omitted; the server continues to enforce its original authorization. No API
was invented, no reflection/download is performed at runtime, and no generic
policy-update method is exposed. The generator checks the original source
hashes before regeneration. The original [Apache-2.0 license](third-party/OpenShell-LICENSE.txt)
is included.

## Limits that remain fail-closed

The bridge also requires Manager phase/image labels, Ready status, accepted current
configuration admission, a loaded active revision and the reviewed static
filesystem/Landlock/process policy. Omitted process identity uses the pinned VM
[canonical sandbox defaults](https://github.com/NVIDIA/OpenShell/blob/6648bd0c290efbc41ba131ee9831ee45cd431f94/crates/openshell-policy/src/lib.rs#L1010), not invented authority.

The bridge refuses unsupported versions, unknown wire fields, missing tokens or
policy evidence, unbound/replaced sandbox IDs, non-MANUAL mode, global policy,
unadmitted configuration and mismatched current effective policy. Only an
additional explicit HTTPS REST rule for curl or the existing pinned Codex paths
from the private Manager-discovered tools record can be approved. The record
fingerprint is included in review identity; drift invalidates callbacks. Native
v0.1.2 executable selectors are path-only; no new guest binary attestation is
claimed. Even with clean prover output, destination hosts matching existing
credentialed endpoints are refused; existing network rules, filesystem, process, Landlock and
middleware bytes must be unchanged. GitHub destinations, credential bindings,
uninspected traffic, private/wildcard destinations, unsupported scope, security
flags and new/unknown prover findings cannot be approved through this P1 bridge.
Unsupported complete proposals can be rejected or inspected; incomplete native
data permits notification/manual fallback only.

Rejection does not have a server-side review-token precondition. Manager checks
exact freshness before dispatch under its operation lock and verifies exact
identity/rule plus unchanged policy/provider state afterward. A concurrent
external native reviewer can still edit/approve between those checks; native
rejection can deny/remove access in that race. Such a mismatch is needs_review,
never reported as exact success. No rejection path grants permissions. P1 assumes
one Manager bridge and coordinates Manager operations with the existing lock;
it cannot lock an independent native administrator. If atomic conditional
rejection is an operator requirement, this native version cannot provide it:
stop deployment and request a separate decision; do not weaken checks or add a
broader mutation API.

Unconfirmed approval/load is needs_review, not success; recovery reads native
state and never repeats a mutation. All live acceptance remains SKIP until an
explicitly authorized isolated dummy sandbox proves this host's actual contract.
Existing local authenticated host credentials are reused; if they are absent,
unsupported or need broader authority, report **BLOCKED — end-to-end approval
unavailable** and request an operator decision. This task created none.
